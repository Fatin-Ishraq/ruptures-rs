# ruptures-rs overall review and work list

Reviewed commit: `beb396c147147d6e34e2264e5c2df9e9195aca6a`, version **0.1.1**. Review completed September 10, 2026.

**Overall rating: 6.5/10.** This is a promising, well-explained numerical implementation with substantial tests and useful acceleration. It is not yet reliable enough for the unconditional “same API, same answers” and “every optimal segmentation” claims. The main risks are silent numerical errors, invalid optimality assumptions, and incomplete resource/boundary validation.

This review covers all six Rust source files, the Python package, tests, packaging, CI/release configuration, and benchmark methodology. It distinguishes reproduced failures, static findings, known limitations, and optimization proposals. It is not a guarantee that every defect has been discovered.

## Prioritized defects and risks

P1 = address before expanding production use or repeating the broad correctness claims. P2 = important correctness, compatibility, or engineering work. P3 = lower-impact contract/documentation work. There is no confirmed P0 or demonstrated remote code execution.

### R1 — P1: local signal detail is destroyed by global preprocessing and prefix subtraction

**Reproduced.** Locations: `src/cost.rs:92-126`, `src/cost.rs:143-145`, `src/prefix.rs:130-162`.

For `x = np.r_[np.full(50, 1e10), np.arange(50.)]`, `CostL2().fit(x).error(50, 60)` returns **0**, although the segment is exactly `[0, ..., 9]` and its true squared-deviation cost is **82.5**. At an unrelated regime level of `1e8`, it already returns 88 instead of 82.5. `CostNormal` inherits the wrong variance. For L1, a level of `1e18` causes centering itself to round away local differences: **0 instead of 25**.

Compensated accumulation and global centering do not bound cancellation when a local segment is far from the global mean. Clamping negatives to zero conceals the failure.

**Work:** retain original/local data for suspicious-segment recomputation; use a reliable cancellation estimate or stable block/merge variance representation; avoid unnecessary global centering for L1. Add tests for large differences between regimes, outliers, small late segments, and affine transformations. A uniform offset test alone misses this case.

### R2 — P1: PELT can miss the optimum, and CROPS reports incorrect optimality intervals

**Reproduced; PELT behavior is inherited from the reference.** Locations: `src/detect.rs:213-268`, `src/crops.rs:33-49`, `src/crops.rs:73-85`, `tests/test_crops.py:33-47`.

With `x = np.random.default_rng(86).normal(size=24)`, `Pelt(jump=1, min_size=6).predict(2)` returns `[15, 24]`, objective **29.8079815096**, while the feasible unsplit result `[24]` costs **29.1869264077**. Both packages return the worse answer. Objectives here are independently scored with two-pass NumPy arithmetic and a penalty per segment; a penalty per change changes both totals by the same constant.

CROPS has a separate demonstrable consequence: seed 4, 24 normal samples, `jump=1`, `min_size=3`, range `[0.1, 5]`. At penalty **0.1612561730**, the reported interval assigns `[4, 9, 12, 16, 21, 24]`, objective **20.5182449145**; `[4, 9, 16, 21, 24]` costs **20.4987429186**. This disproves the advertised interval optimality even without proving the competitor is globally optimal.

**Work:** establish an independent unpruned/exhaustive oracle for small instances; repair pruning with minimum-length and grid constraints; audit the explicit positional zip compatibility quirk; establish the pruning inequality for each model. Route CROPS through a solver with proved optimality guarantees. If reference bug compatibility is retained, distinguish that mode from exact optimization. Check entire intervals, coverage, endpoints, and ties; checking only midpoint agreement with reference PELT does not prove completeness.

### R3 — P1: custom subclasses of built-in costs have their error overrides ignored

**Reproduced.** Location: `python/ruptures_rs/detection.py:49` and accelerated `predict()` branches.

Subclass `CostL2`, override `error()` to return zero, then pass it as `custom_cost`. `accelerated` becomes true because dispatch uses `isinstance(..., _RustCost)`. Predictions use the original Rust L2 engine. A 40-point step signal at penalty 1 returns `[20, 40]` although the supplied cost makes `[40]` optimal. The object's own `sum_of_costs()` reports zero, contradicting what the detector optimized.

**Work:** accelerate only explicitly supported implementations whose semantics have not been overridden; route subclasses and modified methods through the fallback unless they explicitly provide an appropriate native engine. Test overridden `fit`, `error`, `sum_of_costs`, and factory-discovered models.

### R4 — P1: allocation guards miss important structures and run too late on some paths

**Static, no dangerous allocations attempted.** Locations: `src/lib.rs:36-105`, `src/lib.rs:202`, `src/detect.rs:128-178`, `src/cost.rs:622-672`, `python/ruptures_rs/costs.py:55-60,249-269`.

- Dynp allocates `K` arrays of `n+1` u32 back-pointers with no prediction-time budget. KernelCPD also materializes every smaller breakpoint list, adding potentially quadratic output/cache storage in K.
- CostRank allocates several `d*d` buffers without a covariance guard. A two-row, 30,000-column input is under 0.5 MiB but its single covariance array is about 6.7 GiB; additional eigensolver arrays increase that.
- AR allocates Python lagged arrays before Rust checks the covariance budget.
- Input conversion may copy large noncontiguous/different-dtype arrays before native checks. L2 and other constructors hold multiple individually legal arrays concurrently; refitting retains the old engine during construction.
- The fixed 4 GiB per-array ceiling neither accounts for peak working memory nor guarantees allocation success on a constrained host.

**Work:** calculate peak live memory with checked arithmetic before conversion/construction/prediction; add Rank, DP, outputs, scratch, and refit estimates; make limits configurable; use fallible reservations where possible. Test refusal with injected small budgets. This is an availability/denial-of-service risk when a service accepts untrusted dimensions or parameters; no remote exploit was demonstrated.

### R5 — P2: the no-panic boundary promise is still violated

**Three tiny reproducers.** Locations: `src/lib.rs:239`, `src/lib.rs:358-363,501-527`, `src/detect.rs:736,743`.

- Public `Window(width=4, jump=2**63).fit(np.arange(10.)).predict(0)` overflows `2 * jump` to zero in release and raises `PanicException`.
- Direct native `window_predict` with empty indices and score `[0,1,0]` indexes outside the indices vector.
- Direct native `CostEngine(np.empty((10,0)), "linear")` indexes an empty signal.

The latter two are lower-level extension misuse; the first reaches the normal Python API. These are Rust panics, not demonstrated memory corruption, but `except Exception` will not catch them.

**Work:** validate dimensions, minimum lengths, vector consistency, parameter feasibility, and every integer operation at each native entry point. `check_params` currently ignores `min_size`. Add native-boundary fuzzing and retain all three regressions.

### R6 — P2: multivariate Normal rewards corrupted input with negative infinity

**Reproduced.** Locations: `src/cost.rs:223-245`, `src/linalg.rs:18-46`.

A NaN in a two-column signal produces `CostNormal.error(...) == -inf`, including on otherwise clean segments after global centering has contaminated the column. Cholesky returns false for both an invalid NaN matrix and a non-positive-definite matrix; the cost maps both to negative infinity, an exceptionally attractive optimization score. Existing NaN propagation assertions exercise Normal only in one dimension.

**Work:** distinguish nonfinite input, singularity, indefiniteness, and factorization failure. Refuse nonfinite signals explicitly or implement consistent propagation; never interpret invalid input as a perfect statistical fit. Extend tests to multivariate covariance models.

### R7 — P2: eigensolver stopping arithmetic overflows/underflows on finite scaled designs

**Reproduced beyond the documented rank limitation.** Location: `src/linalg.rs:72-90`.

The Frobenius norm is computed by summing squared Gram entries. Multiplying a well-conditioned regression design by `1e80` makes this norm infinite; scaling by `1e-100` makes it underflow. The convergence test can then stop before diagonalization. In the supplied regression, NumPy's residual is **0.5442386410**, while this implementation reports **1.2904786064** at both scales.

**Work:** normalize matrices, compute scaled norms, use stable rotation formulas, and return convergence/residual status. Test invariance under predictor scaling and eigenpair reconstruction across wide exponent ranges.

### R8 — P2: a documented regression rank limitation silently changes the objective

**Known limitation confirmed by source and existing documentation.** Locations: `src/linalg.rs:182-208`, `src/cost.rs:862-865`, `docs/differences.md`.

The normal-equation rank cutoff can declare a full-rank design deficient around condition numbers of 1e7, then return zero residual. Documentation is candid, but zero is an optimization decision: it can make a poor segment appear perfect.

**Work:** retain fast normal equations for well-conditioned segments; use direct QR/SVD or a numerically stable segment representation near the cutoff. Distinguish truly rank-deficient reference semantics from an inability of this solver to resolve rank. Warn or refuse if a reliable result cannot be obtained.

### R9 — P2: accepted multivariate AR data does not match reference behavior

**Reproduced, outside the reference's documented univariate AR contract.** Locations: `src/lib.rs:262-282`, `python/ruptures_rs/costs.py:249-269`.

The Python-visible lagged design is built from the original flattened signal; the native design is built after per-column centering. Flattening multiple columns interleaves different offsets, so the transformation is not absorbed by one intercept. For seed 5, shape `(40,2)`, order 2, segment `[5,35)`, costs are **48.5042195405** versus **48.8612305827** even without added offsets.

**Work:** enforce univariate AR input with a clear error, or explicitly specify and independently validate multivariate semantics. Do not accept it silently while claiming parity.

### R10 — P2: failed refits leave contradictory fitted state

**Reproduced.** Location: `python/ruptures_rs/costs.py:55-64`.

Fit a 20-point L2 signal, then attempt a 3-D refit. The refit raises, but `.signal` now holds the rejected 3-D input while `error(0,20)` still returns the old engine's cost of 665. Detector checks and cached state can consequently refer to different datasets.

**Work:** construct all new fitted state in temporaries and commit it atomically on success, or explicitly invalidate the estimator on failure. Include gamma, metric, covariates, Window scores, and KernelCPD cache in the policy.

### R11 — P2: public API parity is incomplete

**Inspected against installed ruptures 1.1.9; representative failures reproduced.** Locations: `python/ruptures_rs/costs.py`, `python/ruptures_rs/detection.py`, `tests/test_robustness.py` public surface test.

Missing examples: `.gram` on Rbf/Cosine/Ml; `.ranks` and `.inv_cov` on Rank; `Dynp.seg`; `Binseg.single_bkp`; `BottomUp.signal`, `.leaves`, and `.merge`. The current `dir(ruptures)` test checks only top-level names, not fitted objects, signatures, return types, or subclass extension points.

**Work:** create an explicit compatibility matrix. Implement lazy, memory-budgeted attributes where practical and test method semantics; document excluded internals/extensions rather than claiming everything. Review pickling, mutability, repeated prediction, and alias-shim behavior separately.

### R12 — P2: declared minimum Rust version is wrong for the lockfile

**Static metadata verification.** Locations: `Cargo.toml:5`, `Cargo.lock`.

The package declares Rust 1.74, but locked Rayon 1.12.0 and rayon-core 1.13.0 require **1.80**. matrixmultiply 0.3.11 requires 1.75 and rustc-hash 2.1.3 requires 1.77. Source builds on the advertised minimum cannot meet the dependency requirements.

**Work:** raise MSRV to a verified supported minimum or choose compatible dependencies; add a locked MSRV CI build. This review inspected metadata rather than installing and executing Rust 1.74.

### R13 — P2: locked PyO3 has known advisories, with no affected use site found here

**Version-level finding, exploitability not demonstrated.** Location: `Cargo.toml:15`, `Cargo.lock` (PyO3 0.23.5).

- [RUSTSEC-2025-0020](https://rustsec.org/advisories/RUSTSEC-2025-0020.html): `PyString::from_object` can read beyond string data; fixed in 0.24.1.
- [RUSTSEC-2026-0177](https://rustsec.org/advisories/RUSTSEC-2026-0177.html): closure creation lacks a required Sync bound; fixed in 0.29.0.

No uses of the affected string-construction or closure APIs were found in this package's source. This is a reason to upgrade and establish advisory monitoring, not evidence of a reachable exploit. The separately checked RUSTSEC-2026-0013 applies to the 0.28 series, so it is not applicable to 0.23.5.

**Work:** migrate PyO3 and rust-numpy together to compatible patched versions, validate the abi3/Python/platform matrix, and add cargo-audit or equivalent plus Python dependency auditing. Use documented, reviewed exceptions if an advisory is genuinely unreachable. This was a targeted advisory review, not a complete vulnerability scan.

### R14 — P2: CI can pass with the principal correctness oracle absent

**Static.** Location: `.github/workflows/ci.yml:66-78`.

Reference installation is allowed to fail on every OS/Python job; differential modules then skip at import time. This is reasonable for unsupported reference environments, but also allows all compatible jobs to go green after a packaging/network regression removes the oracle. The reference is also unbounded above by `>=1.1.9`, despite the explicit 1.1.9 compatibility claim.

**Work:** make at least one pinned-reference lane mandatory and fail if its expected differential tests skip. Keep separate reference-free platform lanes. Move independent CROPS correctness tests out from behind the module-level `importorskip`. Test minimum/current NumPy, declare toolchain consistency, and execute representative shipped cross-platform wheels rather than only building them.

### R15 — P2: argument validation silently truncates values and disappears under optimization

**Reproduced truncation; assertions inspected.** Locations: `python/ruptures_rs/costs.py:70`, `python/ruptures_rs/detection.py:129-136,156-163,226-247,309`.

`Binseg.predict(n_bkps=1.9)` silently requests one breakpoint; segment boundaries also use `int()` rather than an integer protocol. Multiple required-argument checks use `assert`, so `python -O` removes them. Penalty/epsilon finiteness and fitted-state checks are inconsistent across detectors.

**Work:** centralize integer, range, finiteness, stopping-rule, and fitted-state validation. Preserve intentionally accepted whole-valued floats where documented. Replace validation assertions with explicit exceptions and test both normal and optimized Python.

### R16 — P3: distribution advertises typing support it does not ship

**Wheel inspection.** Location: `pyproject.toml:27`.

`Typing :: Typed` is declared, but the wheel contains neither `py.typed` nor type stubs and much of the public interface lacks annotations.

**Work:** ship complete useful public annotations and a PEP 561 marker, with a type-checking consumer test, or remove the classifier until that support exists.

## Optimization and structural work

These are improvement proposals, not additional security findings. Preserve deterministic tie rules and rerun independent accuracy checks after every numerical optimization.

| ID | Priority | Work | Expected benefit and verification |
|---|---|---|---|
| O1 | High | Replace BottomUp's repeated full sorting/front removals with heaps and stable neighbor links; select midpoint grid candidates arithmetically | Removes avoidable quadratic or worse management overhead. Preserve `(gain,start)` tie order and lazy invalidation. |
| O2 | High | Index Dynp arrays by candidate position rather than raw sample index; special-case K=0; use serial execution below a measured parallel threshold | Changes back-pointer storage from O(K*n) to O(K*n/jump), reduces unused work and Rayon overhead. Keep the terminal non-grid endpoint. |
| O3 | High | For a fixed Mahalanobis metric, prefix-sum scalar `x_i^T M x_i` plus vector `x_i` | Avoids `(n+1)*d*d` storage; queries still evaluate the mean quadratic form in O(d²). Verify against Decimal and nonsymmetric-metric policy. |
| O4 | Medium | Store symmetric covariance prefixes in packed form; reuse per-worker matrix/vector scratch for Normal/Rank/Linear/AR | Roughly halves symmetric storage and removes repeated heap allocations inside DP cells. Measure peak RSS and multithread correctness. |
| O5 | Medium | Use dense candidate-indexed arrays and reusable candidate buffers for PELT | Removes hash lookup and allocation overhead; do this after R2 so it does not further entrench faulty pruning. |
| O6 | Medium | Release the GIL during native cost construction after copying/extracting Python-owned data and parameters | Predict releases the GIL, but O(n²) kernel fitting and other native construction currently hold it. Verify thread responsiveness and safe lifetimes. |
| O7 | Medium | Offer an explicit lower-memory kernel backend or opt-in approximation | The current dense prefix table prevents large kernel workloads; for KernelCPD, compare with streaming kernel DP before claiming the reference has the same memory requirements. Approximate gamma/features need separate accuracy claims. |
| O8 | Medium | Persist reusable Binseg/BottomUp search state across predictions | Their native caches are reconstructed for every prediction, unlike the reusable fitted-state opportunities. Define cache invalidation and memory limits first. |
| O9 | Medium | Split detector/cost modules by algorithm, share validation, and separate bindings from the numerical core | Makes numerical contracts and compatibility behavior easier to test. Avoid duplicating feasibility logic without a cross-language contract test. Remove unused direct dependencies such as ndarray if confirmed unnecessary by the build. |
| O10 | Medium | Make benchmark output self-describing and distribution-based | Record commit, package/compiler versions, CPU/thread count, input hash, warmup, all samples, medians/spread, peak RSS, and fit/predict timings. Fail or clearly quarantine mismatched rows; mark skipped reference runs as unmeasured. |

O1 is supported by both source inspection (`src/detect.rs:526,553,610,614`) and a small local scaling probe: BottomUp, random normal signal, `min_size=2`, `jump=1`, three changes, prediction only:

| Samples | Time |
|---:|---:|
| 2,000 | 0.0080 s |
| 4,000 | 0.0293 s |
| 8,000 | 0.1179 s |
| 16,000 | 0.4836 s |
| 32,000 | 6.7888 s |

These are single local timings, not a replacement benchmark or guaranteed scaling law. They show why larger greedy workloads deserve profiling; the repeated sorting/vector movement is independently visible in the code.

Other structural/security maintenance: pin third-party CI actions to reviewed commit hashes, define default `contents: read` permissions, retain job-scoped OIDC publishing, add dependency-update automation, and provide a security reporting policy. These are hardening opportunities; repository/organization permission defaults were not inspected, so excessive live token permissions are not asserted.

## Execution order and acceptance criteria

1. **Establish the correctness gate:** promote the review regressions into appropriate test modules during fixes; add independent exhaustive small-signal oracles. Stop using reference equality as the only optimality criterion.
2. **Correct outputs:** R1 numerical stability, R2 PELT/CROPS, R3 custom dispatch, then R6–R9 covariance/regression contracts. Exit when known counterexamples pass and small exhaustive/model-specific properties hold.
3. **Protect runtime boundaries:** R4 allocation budgets, R5 native validation, R10 atomic refits, R15 argument validation. Exit when malformed inputs produce ordinary exceptions, small injected budgets refuse predictably, and failed fits have coherent state.
4. **Repair release/compatibility guarantees:** R11 API matrix, R12 MSRV, R13 dependencies, R14 mandatory oracle CI, R16 typing. Exit with clean-wheel consumer checks and the declared platform/version matrix exercised.
5. **Optimize measured bottlenecks:** O1–O6 first, followed by kernel backend and reusable caches. Require objective/accuracy parity, recorded timings, and peak-memory measurements for each change.
6. **Align documentation with demonstrated behavior:** qualify complete API/identical-answer/optimality claims; explain default jump/grid resolution; avoid describing skipped reference benchmarks as proof that the reference cannot run; describe the widest CROPS regime as a stability heuristic, not a general statistical model-selection guarantee.

## Rating rationale

| Dimension | Score | Reason |
|---|---:|---|
| Architecture/readability | 8/10 | Clear coarse FFI boundary, compact package, useful explanations; native modules and validation need separation. |
| Numerical/algorithmic correctness | 5/10 | Strong ordinary-case parity and some Decimal oracles; reproduced silent failures and incorrect optimality claims matter substantially. |
| Safety/robustness | 5.5/10 | Safe Rust and existing guards are good foundations; panic, allocation, invalid-state, and dependency gaps remain. |
| Compatibility | 6/10 | Core workflows work; overrides, fitted attributes, methods, and edge contracts are incomplete. |
| Performance/scalability | 7.5/10 | Real structural acceleration; avoidable sorting, memory growth, allocations, and coarse parallel work remain. |
| Tests/release engineering | 7/10 | 1,392 passing Python tests, Rust tests, wheels, and sdist CI; oracle independence, mandatory lanes, and MSRV need work. |
| Documentation/claims | 6.5/10 | Good numerical explanations and limitations; prominent guarantees are stronger than the evidence. |

The overall **6.5/10** is an engineering judgment, not a measured probability of correctness. The codebase has a strong foundation; fixing silent output errors and proving the advertised guarantees will improve its readiness more than adding further speed claims.
